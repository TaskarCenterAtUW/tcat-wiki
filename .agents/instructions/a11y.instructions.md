# Documentation accessibility

Apply these requirements to authored documentation. They implement WCAG 2.2 Level AA within Markdown's capabilities.

## Required

- Preserve a logical, non-skipping heading hierarchy. The frontmatter title supplies the page title; make authored headings descriptive and unique within their level.
- Give every informative image concise alt text that conveys its purpose. Use `alt=""` only for truly decorative images. Light/dark image pairs must have equivalent alt text.
- Use descriptive link text that is understandable out of context. Do not use bare URLs or vague text such as "here" or "click here."
- Use tables only for tabular data, with meaningful column headers. Do not put essential instructions solely in a complex table.
- Write sequential procedures as ordered lists. Describe controls by their visible label and purpose, not color, position, shape, or pointer action alone.
- When documenting an available keyboard method, include it. Do not invent shortcuts or claim a mouse-only workflow is keyboard accessible.
- Use clear, plain, active language. Define necessary specialized terms on first use and use respectful, inclusive language that follows applicable community preferences.
- Do not make color the only way to distinguish status, choices, or instructions. If adding authored HTML or styling, use project styles that meet 4.5:1 text contrast and 3:1 non-text/focus contrast.

## Authored HTML and embedded UI

- Prefer native semantic HTML. Add ARIA only when native semantics cannot express the required name, role, state, or property.
- Ensure every interactive control has a persistent visible label, keyboard operation, visible focus, predictable tab order, and no keyboard trap.
- Associate form controls with labels, help, and errors; identify invalid input and explain how to correct it.
- Provide meaningful text alternatives for informative SVGs and hide decorative graphics from assistive technology.

## Before completing documentation work

Check headings, image alternatives, links, tables, instructions, and color-only references. Fix violations rather than claiming content is fully accessible; manual assistive-technology testing may still be required.
