# What future capabilities are planned for AccessMap?

## Short Answer

Planned AccessMap capabilities should be described only from a current roadmap or other authoritative source. A planned idea is not current functionality, and its timing or final behavior should not be assumed.

## Significance

Separating current tools from future plans prevents agencies and users from making decisions based on features that are not available or supported.

## What This Means

- Check the date and authority of the roadmap source.
- Label proposed, planned, experimental, and available capabilities distinctly.
- Recheck the current product documentation before giving operational guidance.

## What This Does Not Mean

A roadmap item is not a release, commitment, support guarantee, or substitute for current documentation.

## How To Use This

Answer the current capability question first, then mention a relevant future plan only when it is sourced and clearly labeled.

## Example

A partner asks whether a proposed routing feature can be used in a current project. Staff explain the currently documented options and identify the proposal as future or unverified.

## Assistant Guidance

Do not invent roadmap items, dates, or commitments. Cite the current source and abstain when future-capability information cannot be verified.
