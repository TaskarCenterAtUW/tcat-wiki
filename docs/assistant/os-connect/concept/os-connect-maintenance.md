# Who maintains OS-CONNECT?

## Short Answer

OS-CONNECT maintenance is a coordinated activity involving technical stewardship, release management, issue review, local or jurisdictional knowledge, validation, documentation, and communication. The responsible roles and cadence depend on the current governance and release process.

## Significance

Maintenance keeps a shared dataset useful as pedestrian conditions, sources, schemas, and user needs change.

## What This Means

Track source updates, construction and issue reports, corrections, validation, schema changes, release versions, known limitations, and communication with contributors and users.

## What This Does Not Mean

Maintenance is not guaranteed to capture every change or synchronize every connected product. A public release may still be incomplete or outdated for a specific location.

## How To Use This

Use current local records for operational decisions, report discrepancies with evidence, preserve version and provenance, and check release notes before relying on an update.

## Example

A steward reviews a jurisdiction's correction, validates the evidence, records its disposition, and notes whether it appears in a later public release.

## Assistant Guidance

Do not assign a maintainer or update schedule without evidence. Cite governance and release information and abstain when ownership or current status is unknown.
