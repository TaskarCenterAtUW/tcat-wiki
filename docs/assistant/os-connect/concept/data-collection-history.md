# How was OS-CONNECT collected?

## Short Answer

OS-CONNECT collection history should be described from the documented sources, processing steps, imagery or other inputs, validation activities, and release metadata for the dataset in question. Methods and coverage can vary across releases or areas.

## Significance

Collection history explains why some features or attributes may be inferred, incomplete, differently represented, or tied to an earlier physical condition.

## What This Means

Check the release notes and metadata for source dates, geographic scope, automated processing, human or community validation, schema, and known limitations. Preserve that provenance when using or transforming the data.

## What This Does Not Mean

A collection method does not guarantee current or complete conditions, and the existence of imagery or machine learning does not prove that every feature was detected or verified.

## How To Use This

Use the history to select appropriate validation and interpret results. Ask for the exact release and area before making claims about how a feature was collected.

## Example

A reviewer sees that imagery in an area predates construction and treats affected features as time-sensitive rather than assuming the release reflects current conditions.

## Assistant Guidance

Do not generalize one collection workflow to every release. Cite the documented history and abstain when the source or processing record is unavailable.
