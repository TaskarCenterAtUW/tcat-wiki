# Who is responsible for updates?

## Short Answer

Responsibility for OS-CONNECT updates depends on the source, release, governance arrangement, and feature or jurisdiction involved. Publishers, technical stewards, jurisdictions, contributors, and communities may have different roles.

## Significance

Clear update responsibility helps users know where to report changes and prevents assumptions that one viewer or publisher maintains every underlying feature.

## What This Means

Check release metadata and governance documentation for source ownership, local maintenance, issue review, validation, release management, and communication responsibilities.

## What This Does Not Mean

The organization hosting a map does not automatically own or update every source. A submitted issue does not guarantee that the responsible party will accept or publish a change.

## How To Use This

Use local authoritative records for current operations, send corrections through the verified channel, retain the release and evidence, and track the result.

## Example

A jurisdiction reports a current sidewalk change while the shared steward manages release review. Each responsibility is retained separately.

## Assistant Guidance

Do not name a maintainer or cadence without evidence. Distinguish owner, steward, publisher, and contributor and abstain when governance is unclear.
