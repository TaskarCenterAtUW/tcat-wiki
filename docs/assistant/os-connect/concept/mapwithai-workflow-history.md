# What happened to the older OpenSidewalks / MapWith.ai Tasking Manager workflow?

## Short Answer

The older OpenSidewalks and MapWith.ai Tasking Manager workflow should be treated as historical context unless current project documentation confirms that a step or tool remains supported. Current mapping projects should follow the active project, schema, and stewardship guidance.

## Significance

Historical workflows can explain how earlier mapping efforts were organized, but stale instructions can lead users to obsolete tools, links, or assumptions about data transfer.

## What This Means

- Identify the date, project, tool, and data format described by the older instructions.
- Compare each step with current OpenSidewalks, OSM, and Tasking Manager guidance.
- Confirm current ownership, review, and handoff before starting a new project.

## What This Does Not Mean

- Historical documentation is not automatically a current procedure.
- A prior MapWith.ai workflow does not prove that current data are synchronized or maintained.
- An old tasking project does not establish present authority or support.

## How To Use This

Use historical material to understand provenance, then replace operational steps with current documented guidance. Ask the project steward when the transition between workflows is unclear.

## Example

A mapper finds an older tutorial that references MapWith.ai. Before using it, the mapper checks the current project documentation and confirms the active editor, schema, and review path.

## Assistant Guidance

Label historical claims clearly, cite the dated source, and do not provide obsolete URLs or tool instructions as current. Abstain when the current replacement workflow cannot be verified.
