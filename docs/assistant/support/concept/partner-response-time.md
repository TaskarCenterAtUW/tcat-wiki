# What response time should external partners expect?

## Short Answer

Unless a current service commitment says otherwise, external partners should be given an honest expectation that response time depends on the question, evidence, responsible team, and urgency. Staff should not invent a guaranteed service level.

## Significance

Realistic timing helps partners plan follow-up and avoids turning an informal estimate into a commitment about support, correction, or release.

## What This Means

- Acknowledge receipt when possible and identify the next verification step.
- Give a timeframe only when it is documented or confirmed for that request.
- Explain dependencies such as review, validation, and release.

## What This Does Not Mean

No stated response time guarantees resolution, correction acceptance, or publication. Data-release timing is not necessarily the same as support-response timing.

## How To Use This

Ask the responsible team for a current estimate when timing matters, and distinguish a support reply from a dataset release or product deployment.

## Example

A partner asks when a reported data issue will be fixed. Staff explain the current review dependency and avoid promising a release date that has not been confirmed.

## Assistant Guidance

Do not invent SLAs or dates. Cite any published commitment, label estimates as estimates, and abstain when ownership or timing is unknown.
