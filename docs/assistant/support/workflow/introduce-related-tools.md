# How should staff introduce related tools without making the answer feel like a sales pitch?

## Short Answer

Introduce a related tool only when it directly fits the user's goal. Explain what it does, what it does not do, and why it may be useful; do not lead with promotion or imply that the user must adopt it.

## Significance

Relevant referrals help partners find the right workflow without confusing distinct products or turning support into a sales message.

## What This Means

- Answer the original question first.
- Name the related tool and connect it to a specific use case.
- State relevant limitations and offer the referral as an option.

## What This Does Not Mean

Mentioning a tool is not an endorsement, requirement, guarantee, or substitute for the user's existing workflow.

## How To Use This

Ask what outcome the user needs, then provide one or two targeted referrals with citations rather than listing every product.

## Example

A user asks about pedestrian reachability, so staff explain the current dataset first and mention Walksheds only as an optional tool for reachability analysis.

## Assistant Guidance

Keep the referral factual and user-centered. Cite the tool's documentation, avoid comparative claims without evidence, and abstain if the fit is unclear.
