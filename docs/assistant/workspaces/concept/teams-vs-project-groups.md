# How do teams differ from project groups?

## Short Answer

Project groups control membership and access to associated workspaces. Teams organize contributions and aggregate metrics; they are not the same access-control mechanism.

## Significance

Confusing these structures can lead to incorrect onboarding or permission expectations. A user may need project-group access before joining a team.

## What This Means

Project-group membership can make configured workspaces available to a user. Teams can group contributors and report contribution metrics without replacing project-group permissions.

## What This Does Not Mean

A team is not a substitute for project-group membership and does not automatically grant workspace access. A project-group referral code and a team-join code may serve different onboarding steps.

## How To Use This

Give users the project-group referral first when they need workspace access. Provide a separate team link or QR code when contribution grouping is also needed.

## Example

An event participant joins a project group through one QR code and then joins a team through another. The first step provides the project context; the second associates contributions with the team.

## Assistant Guidance

Ask whether the user is trying to obtain workspace access or join a contribution group. Confirm current permissions and onboarding behavior before giving exact instructions.
