# Workspaces public vs private data

## Short Answer

Workspace data is sandboxed and may be private to its project group until explicitly exported and published through the applicable TDEI workflow.

## Significance

The boundary protects review, collaboration, and controlled release while edits are being prepared.

## What This Means

Users can edit and review workspace data without changing the public source or released dataset. External app access and TDEI publication are separate configuration or workflow steps.

## What This Does Not Mean

Private workspace data is not automatically public, and a workspace's visibility setting is not the same as release status.

## How To Use This

Check project-group membership, workspace access, external-app settings, export state, and TDEI release status separately.

## Example

A team tests a sidewalk edit privately, reviews it, exports it, and publishes a new TDEI version only after approval.

## Assistant Guidance

Ask which audience, environment, and release state are involved. Do not promise public visibility from a saved edit.
