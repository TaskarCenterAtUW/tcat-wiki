# How does Workspaces support collaborative accessibility editing?

## Short Answer

Workspaces supports collaborative accessibility editing by allowing configured users and tools to make feature or attribute changes in a shared workspace, group them into reviewable edits, and coordinate review before export. Current roles, editors, and features depend on workspace configuration.

## Significance

Accessibility mapping often combines local knowledge, field observations, desktop editing, and review. A shared workspace can keep those contributions organized without publishing them automatically.

## What This Means

Set roles and scope, use supported editors, record sources and uncertainty, coordinate overlapping edits, inspect changesets, and apply the workspace's review and export gates.

## What This Does Not Mean

Collaboration does not certify an accessibility condition, guarantee agreement, or automatically update TDEI, OpenStreetMap, or downstream products. A shared workspace is not necessarily a public dataset.

## How To Use This

Use the current workspace documentation, provide accessible participation options, keep observations distinct from verified data, and document unresolved issues for the responsible reviewer.

## Example

A jurisdiction provides source data, community members add observations, and a manager reviews the resulting changesets before deciding whether to export a new dataset version.

## Assistant Guidance

Do not promise a role, editor, or export behavior without current evidence. Ask for the workspace, user role, source, and intended action, and abstain when configuration details are missing.
