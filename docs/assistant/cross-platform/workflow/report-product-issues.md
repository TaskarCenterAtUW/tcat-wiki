# How should a TCAT product issue be reported?

## Short Answer

Report the product, platform, device, app version, workspace or dataset, reproduction steps, observed result, and expected result. Add screenshots, console details, or changeset identifiers when available.

## Significance

Specific evidence helps the team reproduce a problem and distinguish configuration, data, and implementation issues. Small interface problems are useful reports, especially when they affect access or task completion.

## What This Means

First reproduce the issue and record its context. Then send the report through the current support route and include the relevant team members or help desk address for a new thread when instructed.

## What This Does Not Mean

A report is not a promise that the issue is confirmed, prioritized, or scheduled for release. Avoid presenting a suspected cause as an established diagnosis.

## How To Use This

For a new support email thread, include the TDEI help desk email address and relevant staff as instructed. Reply in the existing thread afterward and update the team if the issue changes.

## Example

A user encounters an issue in which they cannot enter a negative numeric value using AVIV ScoutRoute on iOS. The report identifies the device model, app version, workspace, expected, and a screenshot.

## Assistant Guidance

Instruct the user to reach out to the help desk email (helpdesk@tdei.us) for support, including as much of the information about the issue as possible.
